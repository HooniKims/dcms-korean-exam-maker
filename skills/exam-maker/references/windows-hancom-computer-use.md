# Windows 한글 직접 편집과 전체 시험지 검증

사용자 지정(2026-10-05): Windows에서는 Codex의 Computer Use로 설치된 한컴 한글을 바로 열어 원안지를 작성·수정한다. Mac에서 한글이 없었던 이전 제한을 Windows에 이어 적용하지 않는다.

먼저 [자동 환경 준비](environment-bootstrap.md)를 실행한다. 한글 이름·연도·설치 경로를 고정하지 말고 보고서의 실제 Hwp.exe 후보와 현재 Computer Use 앱 목록을 함께 확인한다. HWPX 에디터 스킬 설치는 이 선행 단계에서 처리한다.

## 실행 경로

- **Windows + 한컴 한글 + Computer Use:** 이 경로가 기본이다. 편집 요청 자체가 실행·작업 사본 편집·저장·검증의 허가이므로 “한글로 열까요?”를 다시 묻지 않는다. `computer-use` 스킬의 SKILL.md, guidance.md, confirmations.md를 읽고 해당 런타임을 초기화한다. 자동 스킬 선택을 끄지 않는다.
- **Windows + 한글, Computer Use 미제공/실패:** 한컴의 문서 COM API가 있으면 보조 경로로 사용한다. 화면에서 실제 편집한 것과 COM으로 처리한 것을 구분해 기록한다. 미제공 도구를 호출했다고 주장하지 않는다.
- **Mac 또는 한글 미설치:** 실제 OS와 설치 상태를 확인한다. 원고·후보 DOCX·원본 기반 HWPX 사본의 구조 검사를 진행할 수 있지만, 다른 렌더러만 보고 ‘한컴 최종 검증 완료’라고 하지 않는다. 사용자가 Windows 검증을 요청했다면 그 단계는 미완료로 표시한다. Windows용 `@oai/sky`를 Mac에서 무조건 실행하거나 COM을 호출하지 않는다.

Computer Use 도구는 실행 시 검색해 로드한다. 설치 경로와 창 ID는 PC·세션마다 다르므로 하드코딩하지 않는다. 현재 런타임의 초기화 예:

```js
if (!globalThis.sky) {
  const { sky } = await import('@oai/sky');
  globalThis.sky = sky;
}
globalThis.apps = await sky.list_apps();
nodeRepl.write(JSON.stringify(apps));
```

반환된 한글 앱을 선택하고, 창이 없으면 그 앱 ID로 `sky.launch_app`을 실행한다. `list_windows`/`list_apps`로 새 창을 확인한 후 정확한 창 하나를 선택한다. 문서 제목만으로 입력 위치를 추정하지 않는다.

## 직접 편집

1. 사용자가 지정한 원본과 최신 산출물을 읽고 해시를 기록한다. 새 경로에 작업 사본을 준비한다. 현재 문서에 저장하지 않은 사용자 수정이 있으면 덮어쓰지 않는다.
2. 한글2024에서 확인한 **불러오기 단축키는 Alt+O**다. Ctrl+O는 문서 끼워 넣기이므로 파일 열기로 쓰지 않는다. 문서 처음은 Ctrl+PageUp으로 이동하고 화면을 다시 확인한다. 메뉴/단축키는 버전이 다르면 실제 화면을 따른다. 한글의 **불러오기**에서 작업 사본의 절대 경로를 입력한다. 화면을 확인하고, 표 셀·본문·머리말 등 실제 편집 영역에 포커스를 둔다.
3. 상단은 원래 표 셀 안의 값만 바꾼다. 본문은 지문·발문·보기·선택지를 문항 블록으로 넣는다. `Ctrl+A`로 전체 문서를 지우거나 p0에 딸린 구역·단·꼬리말 제어를 제거하지 않는다. [원안지 보존 규칙](deungchon-original-form.md)을 따른다.
4. 많은 문항의 정리·서식 준비에는 파일 도구와 원본 복제 방식의 HWPX 편집을 보조로 쓸 수 있다. 이 경우 ‘전체를 화면으로 입력했다’고 하지 않는다. 준비본을 한글에서 실제로 열고, 상단 셀 변경과 본문 변경을 직접 실행해 저장·재열기까지 확인한다. 이미 열린 파일을 뒤에서 덮어쓰지 않는다.
5. 한 번의 UI 동작 뒤 상태를 다시 확인한다. 바뀐 화면에는 이전 요소 인덱스·좌표를 재사용하지 않는다. 큰 접근성 트리는 필요한 메뉴·포커스·상태 표시줄만 출력하고, 스크린샷 base64를 텍스트로 출력하지 않는다.
6. 한글 **저장하기/다른 이름으로 저장하기**로 새 HWPX를 저장한다. **파일 → PDF로 저장하기**로 전체 쪽을 내보낸다. 실제 프린터에 인쇄할 필요는 없다. 파일 대화상자에서는 경로만 입력하며 명령을 실행하지 않는다.
7. 저장본을 닫고 다시 연다. 대표 문항과 상단 값을 다시 편집할 수 있는지, 쪽수와 조판이 유지되는지 확인한다. 최종 결과는 한글에서 열어 보여 준다. 무관한 사용자 창을 닫거나 한글 프로세스를 일괄 종료하지 않는다.

파일 접근 권한·보안/개인정보 요청은 Computer Use가 대신 처리하지 않는다. 실제로 그런 창이 나타난 때만 사용자에게 해당 창 처리를 요청하고 이유를 설명한다. 일반 파일 열기·저장에 매번 별도 승인을 요구하지 않는다. 경고 창을 숨기는 옵션으로 권한 요청을 우회하지 않는다.

## 이어짐 표시와 하단 여백

사용자의 추가 지정(2026-10-05)은 [기출 기반 하단 배치 규칙](continuation-and-bottom-space.md)을 따른다. 홀수/짝수 이어짐 표시, 마지막 쪽 생략, 모든 비최종 단의 하단 사용량을 실제 PDF로 검사한다. 단순히 글상자를 바닥에 놓아 본문 공백을 채웠다고 계산하지 않는다.

## 저장 전후의 비교 기준

한글은 저장하면서 사용하지 않는 스타일을 정리하고 ID를 바꾸거나 이미지를 재인코딩할 수 있다. 그러므로 두 검사를 구분한다.

- **원본 기반 준비본:** `check_school_form.py`로 원본의 보호 구조·미디어·기존 스타일 보존을 엄격하게 비교한다.
- **한글에서 편집·저장한 최종본:** 원본을 결과물로 교체하여 기준을 낮추지 않는다. 용지·여백·단·상단 표의 격자/치수/위치·외곽선·꼬리말/교표의 의미와 실제 PDF 좌표를 비교한다. ID/ZIP바이트 변화만으로 레이아웃 손상이라고 단정하거나, 반대로 모든 차이를 무시하지 않는다. 사용된 글꼴·크기·강조는 실제 텍스트 런까지 연결해 검사한다.

## 전체 시험지 테스트

상단 글자 몇 개만 바꾼 시험은 전체 작성 검증을 대신하지 않는다. 산출물에 실제 후보가 있으면 지문·문항·선지·보기·서술형 조건까지 포함한 추천 조합을 **검증용 사본**으로 작성한다. 이는 새 최종 문항 선택을 확정하는 행위가 아니다. 시험일·교시 등 미확정 값은 비워 두거나 명시적인 검증값으로 기록한다.

- 선택한 원본 후보 번호 ↔ 시험지 번호, 문항 수·배점 합계, 제거한 교사용 메모와 교체 후보를 기록한다. 원자료와 새 시험지의 텍스트를 문단별로 대조해 누락·중복을 찾는다.
- 긴 지문10pt·발문11pt, 한양신명조, 부정어만 굵게+밑줄, 참조 밑줄·원문자 뒤 공백을 검사한다. DOCX의 `w:b w:val="false"`/`"0"`/`"off"`는 굵게가 아니다. 요소의 존재만으로 참으로 읽지 않는다.
- 전체 PDF를 렌더링하여 모든 쪽을 본다. 각 쪽 정보표1개, 순차 `No.:n/N`, 본문2단, 외곽선·중앙선·꼬리말·교표, 잘림·겹침·원문자·보기·조건·선지 정렬을 확인한다.
- 발문과 선지/짧은 보기·조건이 갈라지지 않게 한다. 지문 다음의 첫 문항, 지문 출처, 소제목이 홀로 남지 않게 한다. 긴 지문을 한 단보다 큰 분할 불가 블록으로 묶지 않는다.
- 글자 크기를 줄여 쪽수를 고정하지 않는다. 한컴이 계산한 줄 배치로 단 높이를 측정하고 문항 단위로 재배치한다. 첫 쪽 상단은 더 높으므로 쪽마다 실제 사용 가능 높이를 확인한다. 마지막 쪽의 두 단은 가능한 범위에서 균형을 맞춘다.
- 저장 후 재열기·PDF 재출력에서 본문 텍스트·문항 수·쪽수·보호 도형이 유지되는지 확인한다. 상단 값과 본문 편집도 실제로 시험한다.
- 실패한 항목을 고쳐 다시 저장·검사한다. 최종 파일의 해시와 각 검사 결과를 남기며, 해결되지 않은 오류가 있으면 PASS 또는 ‘이상 없음’으로 보고하지 않는다.

이번 검증의 구체적인 범위와 결과는 [실제 문항 검증 기록](native-exam-test-results.md)에 둔다. 특정 샘플의 합격이 모든 후속 분량의 자동 합격을 뜻하지 않으므로 새 시험마다 전체 검증을 반복한다.
