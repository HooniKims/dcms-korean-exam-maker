# 한글 시험지 검증 기록

## 2026-10-07 v1.10.4 모든 쪽 하단 채움·짧은 지문 시작 이동

- 최신 사용자 지시에 따라 마지막 쪽의 큰 여백 예외를 폐기하고, 확정 문항 묶음 사이에 남는 높이를 분배했다. 선택지는160%·앞뒤0을 유지했다. 서술형 한 문항만 있는 마지막 단은 실제 작성 공간을 넓혔다.
- 안내문과 지문3줄만 쪽 끝에 남던 묶음을 다음 쪽 첫머리로 옮기고, 해당 페이지의 정보표·계속 표시·중앙선 앵커도 함께 옮겼다. 질문·정답·배점은 바꾸지 않았다.
- 학생용을 한글2024에서 저장하고PDF로 출력해7쪽 전체를 확인했다.14개 단의 하단 잔여 공간은 계속 표시의 안전 여백을 반영한 검사에서0~3.295mm였으며, 짧은 지문 시작 조각 검사는0건이었다. 지문39문단·답안선12줄의 좌우 대칭과 선택지120개의 간격 검사도 통과했다. 교사용은 동일한 레이아웃과 정답 표시를 구조 대조했으며 별도PDF 출력은 하지 않았다.
- `check_native_roundtrip.py --fill-final-page`를 추가하여 마지막 쪽도 하단 공백 검사에 포함한다. `check_exam_flow.py`는 다음 쪽으로 이어질 지문이 시작 쪽에5줄 미만만 남는 경우를 검출하며, 같은 쪽의 단 이어짐과 완결된 짧은 지문을 구별한다. 회귀 **148개 통과**.
- 이번 요청의 배치 검수는 통과했다. 기존 중앙선 중첩을 일반 검사기가 중복으로 보는 오류와 기존 첫 문항의 배점 줄바꿈 경고는 수정 전후 동일하게 남았다. 전체 일반 검수까지 모두PASS한 것으로 기록하지 않는다. 개인 시험지·정답·로컬 출력물은 저장소에 포함하지 않는다.

## 2026-10-07 v1.10.3 답안선·지문 테두리 좌우 대칭

- 문자 밑줄 답안선은 가운데 정렬하고 문단 좌우 여백과 첫 줄 들여쓰기를 대조한다. 지문·출처의 연결 테두리는 단 경계에서 양쪽을 같은 폭으로 안쪽에 배치하고 글자와 테두리 사이 간격도 같게 한다. 기출의 좌우 비대칭 값은 신규 문서의 강제값으로 사용하지 않는다.
- 역할 명세를 사용하는 `check_symmetric_margins.py`를 추가했다. 과거 비대칭, 왼쪽 정렬 답안선, 경계에 붙은 테두리, 호환 분기 차이, 여백 무시와 들여쓰기 오류의 회귀 검사를 포함해 **144개 테스트를 통과**했다.
- 로컬 학생용·교사용 각각 지문/출처39문단과 답안선6문단의 대칭 구조 검사를 통과했다. 모든 문항 텍스트는 변경 전과 같다. 일반 HWPX XML 오류는0이며, 기존 역할별 문단 간격 및 원본 호환 스타일 경고는 별도로 남는다.
- 한글2024에서 학생용 수정본을 열고 저장·PDF 출력하여7쪽 전체를 시각 검사했다. 좌우 지문 테두리 중심은 각각 약173.487pt/421.334pt, 답안선6줄 중심과 오른쪽 단 중심의 차이는0.01pt 미만이었다. 테두리는 양쪽 단 경계에서 약1mm 안쪽으로 들어간다. 문항 텍스트와 순서도 출력 전후 동일했다. 교사용은 같은 문단 설정과24개 정답 표시를 구조 대조했으며 별도 PDF 출력은 하지 않았다.
- 최초 출력에서 `ignoreMargin=0`은 문단 여백을 테두리에 반영하지 않는 것을 확인하여1로 보정했다. CASE425/DEFAULT850의 네이티브 단위 변환도 검사기에 반영했다. 일반 테두리 검사는 기출의0과 수정본의1을 허용하고, 대칭 전용 검사는1을 요구한다. 개인 시험지는 저장소에 포함하지 않는다.

## 2026-10-07 v1.10.0 출처·구분선·정답 표시

- 출처를 `- 작가명, 「작품명」`으로 정리하고 발췌·재구성·쪽수 등 편집 설명은 별도 근거에 남기는 사용자 지시를 반영했다. 원문에서 작가를 확인하며 작품명 기호를 보존한다.
- 구분선 목표를 다른 쪽 선의 끝에서 용지 높이−아래 여백−꼬리말 여백으로 바꿨다. 모든 쪽과 한 쪽짜리 문서를 검사한다. 같은 높이로 짧은 여러 선, 끊긴 이음새, x좌표·굵기 차이, 하단 초과를 회귀 검사한다.
- 정답 선택지 전체를 `hp:markpenBegin`/`hp:markpenEnd`로 표시하는 교사용 사본 도구를 추가했다. 여러 런·줄바꿈을 포함한 텍스트 및 서식을 보존하는지 검사한다. 최종 번호와 정답표로 대조하며 학생용 원본은 보존한다.
- Python 회귀 검사 132개를 통과했다. 로컬 문서의 출처 9개, 정답 표시 24개는 내용·구조를 대조했다. 실제 시험과 정답은 공개 저장소에 넣지 않았다.
- **새 수정본의 한글 저장·재열기·PDF 시각 검증은 파일 접근 확인창에서 대기 중이다.** 위 결과는 코드/구조 검사 결과이며, 과거 네이티브 조판 합격을 이번 수정본의 합격으로 재사용하지 않는다.

## 2026-10-06 긍정·부정 배분 적용 샘플

스킬 v1.9.1의 발문 배분을 기존 샘플에 적용했고, 검증에서 확인한 수정·정답 동기화 절차를 v1.9.2에 반영했다. 아래 v1.8.3 기록은 수정 전 레이아웃 검증 이력이다.

- 선택형22문항은 긍정15·부정7이며, 선택형78점+서술형4문항22점=100점을 유지했다. 정답을 독립적으로 풀이하고, 최종 시험지 번호와 교사용 정답·해설·배점을 대조했다.
- 기존 문항의 지문 범위와 필수 답안 조건, 근거를 한정하는 발문 표현과 정답 선택지의 불일치를 수정했다. 교사용 자료의 정답 번호별 개수와 서술형 채점 조건도 실제 문항에 맞췄다.

- 최초 재조판에서 문항 묶음이 밀려 7쪽이 된 문제를 문항 사이 간격 조정으로 해결했다. 글자 크기와 선택지160%·추가 간격0을 유지했다. 새로 마지막 줄로 밀린 배점은 별도 우측 정렬 문단으로 옮겼다.

- 원안지 원본과 수정 전 샘플은 해시로 보존을 확인하고, 이전 산출물은 보관 폴더로 분리했다. 실제 시험 문항·정답·개별 작업 로그는 공개 저장소에 넣지 않는다.

## v1.8.3 물결·배점·마지막 쪽 구분선 검증

2026-10-06. 기존 6쪽 편집 테스트본에 사용자 최종 지시를 반영했다. 기존 문항 내용과 순서를 보존한 **레이아웃 검증용**이며 실제 시험 확정본이나 새 난이도 기준으로 재출제한 문서는 아니다.

### 수정 내용

- 물결18개를 ASCII `~`(U+007E)로 유지하면서 가운데 모양으로 출력되도록 해당 글자에만 Arial 글리프를 적용했다. 한글 글꼴·본문 크기·강조는 보존했다.
- 줄 끝에서 배점이 갈라지거나 배점만 마지막 줄에 있던6곳(6번·서술형2·12번·18번·19번·서술형4)을 수정했다. `(3점)` 등 전체 배점을 별도 다음 문단에 두고 배점만 오른쪽 정렬했다. 발문 본문은 탭과 내어쓰기를 유지했다. 같은 줄에 온전히 들어가는 나머지 배점은 유지했다.
- 마지막6쪽의 중앙 구분선은 기존 내용 끝635.185pt에서 다른 쪽과 같은772.435pt까지 연장했다. 기존 선과 연장선의x좌표297.440pt·굵기0.360pt가 같고 접합부에 틈이 없다. 본문·단 폭·쪽수에 영향을 주는 빈 문단은 추가하지 않았다.
- 공통 지시문은 `[9~12, 서2] 다음을 읽고 물음에 답하시오.` 형태의 굵은 한 줄을 유지했다.

스킬의 기본 예상 평균은100점 기준70점이다. 쉬움40%·보통50%·어려움10%의 배점 비중에 예상 득점률85%·65%·35%를 적용한 기본 모형이며, 실제 자료로 보정한다. 이번 샘플이 이 평균을 달성한다고 검증한 것은 아니다.

### 한글 열기 오류와 수정

초기 작업 사본은 추가한 선의 끝점 네임스페이스가 잘못되어 한글이 읽기 오류를 표시했다. `hp:line`의 끝점을`hc:startPt`·`hc:endPt`로 고쳤다. 이어서 폭0으로 인한 NaN 변환 행렬을 방지하도록 최소1HWPUNIT의 폭을 사용했다. 최종 사본은 정상적으로 열리고 저장·PDF 출력·재열기까지 통과했다. 원본 파일은 손대지 않았다.

Computer Use 입력에서`failed to activate captured window`가 반복되어 지침의 보조 경로인 한글 문서 COM API로 최종 저장·재열기·출력을 수행했다. 화면 입력으로 편집했다고 기록하지 않는다. 파일 접근 보안 확인은 사용자가 직접 처리했으며 우회하지 않았다.
