# 발문 정렬·보기/조건·마지막 배점 집계

2026-10-05 사용자 지시를 반영한다. 근거는 사용자가 HWPX로 저장해 제공한 `2023-3-2-기말-국어-문제지.hwpx`이며, 옛 문항은 재사용하지 않고 개체와 서식만 재사용한다. [원본 및 추출 위치](../assets/teacher-2023-components/source.json)를 확인한다.

## 발문 번호 뒤 탭과 내어쓰기

공통 지시문(2026-10-06 최종 지정)은 **문항 범위와 지시문을 합쳐11pt 굵게 한 문단·한 줄**로 쓴다. 예: `[1~8, 서1] 다음을 읽고 물음에 답하시오.`, `[9~12, 서2] 다음을 읽고 물음에 답하시오.`. 범위 안의 서술형 참조는 `서1`, `서2`, `서3~4`처럼 줄이고 숫자 앞에 공백을 넣지 않는다. 범위를 윗줄로 분리하던 이전 규칙은 폐기한다. 공통 제시물이 글·표·그림 등 자료여도 사용자의 최종 지정에 따라 지시문은 `다음을 읽고 물음에 답하시오.`로 통일한다. 글자11pt·굵게·장평100%·기존 단 폭은 유지한다. 실제 한글에서 넘칠 때만 해당 지시문 전용 글자 모양의 자간을 작게 조절한다. 이번 문구 수정본은 기존 조합의 자간을 보존하여 `[1~8, 서1]`과 `[9~12, 서2]`에−3%, `[13~22, 서3~4]`에−10%를 적용했다. 다른 범위에서는 이 값을 고정하지 않고 필요한 최소 조정을 실제로 검증한다. 문구를 임의로 `다음 자료를 읽고 답하시오.`로 바꾸거나 범위를 따로 떼지 않는다. 한글 저장본과PDF에서 대괄호 시작부터 끝의 마침표까지 같은 줄인지 검사한다. 지문 테두리와는 일정한2pt 정도의 가독성 간격만 두고 하단 채우기용으로 늘리지 않는다. 실제 서술형 발문 번호와 상단의 문항 유형명은 이 약칭 규칙의 대상이 아니다. 별도 서술형 안내도 굵게 한 줄로 유지한다. 일반 발문 본문의 긍정어 무강조 규칙과 혼동하지 않는다.

`1.\t발문`, `10.\t발문`, `서술형 1.\t발문`처럼 번호 뒤에 실제 탭을 넣는다. HWPX에서는 `<hp:t>` 안의 `<hp:tab/>`이며 공백 여러 개로 흉내 내지 않는다. 번호 길이에 맞는 왼쪽 탭 위치와 문단 내어쓰기를 함께 설정하여 둘째 줄 이후도 첫 줄 본문과 같은 x좌표에서 시작하게 한다. 배점만 다음 줄에 놓을 때는 아래 예외를 적용하고 발문 본문의 탭·내어쓰기는 유지한다.

한글의 문단 왼쪽 여백0, `intent=-탭위치`를 사용한다. 이 값은 한글에서 둘째 줄 이후를 오른쪽으로 이동시킨다. 기본 탭이나 원본의 많은 탭 위치를 그대로 쓰지 말고 번호 폭보다 큰 전용 탭을 추가한다. 샘플의 시작값은 한 자리16pt, 두 자리22pt, 서술형55pt다. 실제 글꼴/번호를 바꾸면 출력 좌표로 다시 확인한다. 단 전체의 위치를 바꾸는 것이 아니라 번호를 제외한 본문 시작점만 맞춘다.

원본에는 내어쓰기가 있으나 실제 탭 문자가 없어 이번 지시대로 보완한다. 문단 모양의 case/default 양쪽 여백에 같은 값을 적용하고 원본 공용 스타일을 수정하지 않는다. 발문11pt, 긍정어 무강조·부정어만 굵게와 밑줄, 기존 번호 강조는 유지한다.

## 물결·배점·마지막 쪽 구분선

2026-10-06 사용자 최종 지시를 적용한다.

- 범위의 물결은 가운데 모양의 **ASCII `~`(U+007E)**로 쓴다. `∼`, `～`, `˜`, `〜`로 바꾸지 않는다. 한양신명조의 해당 글리프가 높게 보이면 물결 한 글자에만 Arial의 Latin/Symbol/Other/User 글꼴 참조를 적용한다. 원래 크기·굵게·자간과 나머지 한글 글꼴은 유지한다. 문자 코드만 확인하지 말고 실제 PDF의 모양도 확인한다.
- `(5점)`이 줄 끝에 온전히 들어가면 발문 뒤에 유지한다. 배점 일부가 다음 줄로 넘어가거나 배점만 마지막 줄에 남으면 **괄호까지 포함한 배점 전체를 다음 줄로 옮기고 배점만 오른쪽 정렬**한다. `(5`와 `점)`을 나누지 않는다. 발문 전체를 오른쪽 정렬하지 않는다. 공백으로 밀지 말고 오른쪽 정렬의 별도 배점 문단을 사용하며, 좌우 여백·들여쓰기·앞뒤 추가 간격은0으로 한다. 기존 발문 번호 탭과 내어쓰기를 보존하고 배점 문단이 발문·보기·선택지와 분리되지 않게 확인한다.
- 마지막 쪽은 본문이 짧아도 가운데 다단 구분선을 다른 쪽과 같은 하단 높이까지 유지한다. 원안지의 단 폭과 본문 흐름을 보존한다. 빈 문단을 쌓아 선을 늘리지 않는다. 기본 다단 구분선이 내용 끝에서 멈추면 같은 굵기·색의 네이티브 선 개체로 부족한 아래 부분만 연장할 수 있다. 종이 기준 위치, 본문 배치에 영향 없음, 마지막 쪽의 안정된 문단에 고정을 적용하고 PDF에서 기존 선과 이어짐·x좌표·굵기·끝높이를 검증한다. 내용 재배치로 끝 쪽이나 내용 높이가 바뀌면 연장선을 제거하거나 좌표를 재계산하며 중복 추가하지 않는다.

`scripts/refine_exam_layout.py`는 **서로 일치하는 한글 저장본·한글 PDF·작성 명세**에서 이 세 항목을 보완하는 헬퍼다. 검증 전 준비 파일이나 이미 보완한 명세에 반복 실행하지 않는다. 원본을 덮어쓰지 않고 새 작업 사본에 출력한다.

```sh
python scripts/refine_exam_layout.py baseline.hwpx --pdf baseline.pdf --manifest baseline-manifest.json --output refined.hwpx --output-manifest refined-manifest.json
```

새 사본을 한글에서 열어 전체 쪽수를 계산한 뒤 저장·PDF 출력하고, 저장본을 다시 열어 재출력한다. 그 후 다음 검사를 실행한다.

```sh
python scripts/check_exam_finish.py final.hwpx --pdf final.pdf --manifest refined-manifest.json
```

선 개체 XML을 직접 준비할 때 `hp:line`의 두 끝점은 **`hc:startPt`·`hc:endPt`**다. `hp:` 끝점은 한글 읽기 오류를 일으켰다. 폭0은 한글 재저장 때 NaN 변환 행렬과 보이지 않는 선을 만들었다. 검증된 헬퍼는 최소1HWPUNIT 폭을 사용한다. XML 문법 통과만으로 성공이라 판단하지 말고 한글 열기 성공, 재저장 행렬의 유한값, PDF의 실제 선, 재열기 결과를 모두 확인한다. 구현 참고: [python-hwpx 지원 명세](https://github.com/airmang/python-hwpx/blob/main/docs/support-matrix.md).

## 원본 네이티브 개체 복제

[재사용 헬퍼](../scripts/native_exam_components.py)의 `Components(header, used_ids=기존_문단과_개체_ID_목록)`를 이용한다. [보기](../assets/teacher-2023-components/example.xml)는 원본 본문 p28의 3행×3열 병합 표(실제6셀)다. 가운데 `<보 기>`가 윗선에 끼어 있는 모양, 셀 병합, 테두리, 너비22941, 안팎 여백을 보존한다. 본문은 마지막 전체 폭 병합 셀에 넣는다. 제목을 본문 첫 줄에 다시 쓰지 않는다.

[조건](../assets/teacher-2023-components/condition.xml)은 원본 p217의 1행×1열 표다. `<조건>` 제목과 조건별 문단을 셀 안에 유지하고 너비22821·안쪽 좌우510·테두리·조건 내어쓰기를 복제한다. 원본 개체의 글꼴은 주로 돋움10pt이며 긴 지문의 한양신명조10pt와 구별한다. 글자처럼 취급 여부는 흐름에 맞춰 정하되 실제 출력에서 위치를 확인하고 변경을 기록한다. 짧은 개체는 발문과 함께 한 단에 두며 셀 내부에서 쪽을 나누지 않는다.

일반 공통 지문은 이전 지시대로 연결된 **문단 테두리**다. 이를 보기 표로 바꾸거나, 반대로 보기·조건을 문단 테두리로 대체하지 않는다. 새 개체의 내용만 치환하고 강조/기호가 있는 내용은 해당 텍스트 런 서식도 보존한다. 헬퍼의 `table(kind, texts)`는 일반 텍스트용이며 강조가 필요한 경우 반환된 셀에 서식 런을 넣는다.

정의 파일의 기존 ID를 다른 문서에 그대로 붙이지 않는다. 헬퍼는 글자·문단·테두리·탭 및 언어별 글꼴 참조를 새 문서 끝에 추가해 다시 연결한다. 원본의 빈 셀용3pt 등 역할별 서식도 보존한다. 과거 문항/정답/날짜는 자산에서 제거했다. 채운 내용의 줄 수에 따라 **높이만** 한글이 계산한 값으로 갱신한다. 임의 축소로 높이를 맞추지 않는다.

## 마지막 배점별 문항 수와 총점

원본 p223의 가운데 `<끝>`과 p229~235의 오른쪽 정렬 문단을 복제한다. 선택형/서술형을 구분하고 `배점 × 문항 수 = 소계`를 배점마다 한 줄씩 쓴 다음 `합계   총점`으로 끝낸다. 원본의 선택형 배점 내림차순, 서술형 오름차순, 같은 유형의 둘째 줄부터 유형명 생략을 유지한다. 한 자리 문항 수/소계 앞의 흰색0은 원본의 자릿수 정렬용이며 다른 글자를 흰색으로 만들지 않는다.

`Components.scoring(choice_scores, constructed_scores)`는 실제 문항별 점수에서 개수·소계·총점을 계산한다. 현재 검증 조합은 선택형4점12문항·3점10문항=78점, 서술형5점2문항·6점2문항=22점, 총100점이다. 원본의24+4문항/80+20점이나 현재 샘플의22+4문항을 후속 시험에 고정하지 않는다. 본문 맨 앞에 중복 합계 안내를 넣지 않는 이전 지시는 유지한다.

## 검증

모든 발문에서 실제 탭 존재·탭 위치와 내어쓰기 일치를 검사한다. 한 자리/두 자리/서술형의 여러 줄 발문을 한글 PDF에서 비교하여 첫 줄 본문과 이어지는 줄의 x좌표가 맞는지 확인한다. 번호가 탭을 밀어내거나 첫 단어 앞에 불필요한 공백이 있으면 수정한다.

원본 개체와 복제 개체의 행열·병합·셀 폭·선·여백·제목·글꼴을 대조하고, 내용 변경에 따른 높이는 한글 재조판 후 확인한다. 끝 부분의 문항 수·소계·총점을 독립적으로 다시 합산한다. 저장·닫기·재열기 후 전체 PDF에서 넘침·잘림·발문과 개체 분리·선택지 간격·하단 여백도 확인한다. 실제 결과와 미확인 사항은 [검증 기록](native-exam-test-results.md)에 남긴다.

`python scripts/check_exam_flow.py final.hwpx --pdf final.pdf --manifest sample-manifest.json`으로 실제 조판된 지시문 한 줄·굵게, 선택형 번호의 읽기 순서,26개 등 현재 모든 발문의 탭·내어쓰기 일치 및 PDF에서 이어지는 줄의 x좌표를 확인한다. 작성 명세에는 `blocks/paras`의 `text`, `role`, `paragraph_id`와 실제 읽기 순서인 `columns`, `pages_planned`, `choice_count`를 기록한다. 이는 자동으로 겹침을 모두 판별하는 도구가 아니므로 전체 쪽 시각 검토를 함께 한다.
