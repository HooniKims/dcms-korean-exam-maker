# 이어짐 표시와 하단 배치

2026-10-05 사용자 지정: 본인 기출문제처럼 다음 쪽·다음 장 표시를 넣고 각 쪽 하단의 큰 공백을 없앤다. 원본 외곽선·꼬리말·교표의 위치를 바꾸지 않는다.

## 기출에서 직접 확인한 방식

`본인_출제모음/23-3-2-중간/2023-3-2-중간-국어-문제지(완성).hwp`의 한컴 PDF 1~4쪽은 홀수 `▶다음 쪽 계속`, 짝수 `▶다음 장 계속`, 마지막5쪽은 생략한다. 표시는 오른쪽 아래, 약10pt이다. `25-3-2-기말-국어-시험지(김형훈 추가 및 수정).hwp` 1~6쪽에서도 같은 홀짝 규칙을 `▶다음 쪽에 계속`/`▶다음 장에 계속`으로 쓰며 마지막7쪽에서 생략한다. 두 자료의 본문은 마지막 문항/조건을 하단 가까이 배치하고, 서술형을 관련 지문 주변에 넣거나 문항 간 간격을 조정한다. 짧은 선지는 가로 배치도 쓴다. 과거 검토용 정답 형광색과 일부 중복 마커는 새 시험에 복사하지 않는다.

## 적용할 규칙

- 이번 사용자 표현을 적용해 **홀수 쪽 `▶다음 쪽으로 계속`, 짝수 쪽 `▶다음 장으로 계속`**을 쓴다. 각 비최종 시험지 쪽에 정확히1개, 마지막에는0개다. 별도 답안지 유무를 시험지의 계속 표시에 섞지 않는다. 쪽수가 바뀌면 전부 재계산한다.
- 본문 프레임 안 우하단, 저작권·교표 위에10pt로 둔다. 본문/조건 상자와 겹치지 않도록 전용 하단 공간을 확보한다. 스페이스·탭·빈 문단을 반복해 바닥으로 밀지 않는다.
- 본문 앵커에 연결한 테두리 없는1셀 표처럼 한컴에서 안정적으로 유지되는 개체를 사용한다. 용지 기준 위치를 쓰고 꼬리말을 편집하지 않는다. 이 원안지 검증에서는 폭11000/높이2177 HWPUNIT, PAPER 기준 왼쪽43000/위77000, 내부 여백283, 오른쪽 정렬의1셀 표를 사용한다. 다른 양식에 수치를 무조건 적용하지 않는다. 저장 후 높이·위치·본문 겹침을 재검사한다.
- 실제 한컴2024 PDF 출력에서 사각형 글상자는 이후 페이지의 숫자 출력 정밀도를 낮춰 기존 꼬리말 글자를 약0.3mm 이동시켰다. 모양만 비슷하다고 합격시키거나 비교 허용치를 늘리지 말고, 테두리 없는 표 등으로 바꾸어 재출력한다.

## 하단 공백 줄이기

2026-10-06 추가 지시: 마지막 쪽 외에는 큰 여백을 남기지 않도록 **문제 배열과 순서를 먼저 조정**한다. 같은 지문 안에서 선택형 순서를 바꾸고 관련 서술형을 함께 배치할 수 있다. 읽기 순서대로 번호를 다시 매기고 원본 후보 대응표·공통 지시문의 범위·답안 번호를 함께 갱신한다. 서로 다른 지문의 문항을 섞거나 아직 제시하지 않은 근거를 요구하는 순서로 만들지 않는다.

기존6쪽 배치에 새 개체/내어쓰기를 넣은 뒤 실제로9쪽이 된 오류가 확인됐다. 이전 버전의 문단 높이와 강제 단/쪽 나눔을 재사용하지 않는다. 실제 한글 저장본의 문항 높이를 다시 측정한 후 나눔을 결정한다. 자연 단 넘김 직후 강제 단 나눔이 겹치면 다음 단이 비거나 번호 없는 쪽이 생길 수 있다. 예정 쪽수와 PDF 쪽수, 각 쪽 상단 정보표와 No.:n/N이 모두 일치해야 한다.

하단 여백을 단순히 문항 사이의 큰 공백으로 옮겨 숨기지 않는다. 문항들의 높이뿐 아니라 해당 단에서 자연스럽게 간격을 둘 수 있는 문항 경계 수를 함께 고려한다. 선택지·조건·보기 내부, 한 줄로 합친 범위·공통 지시문 내부, 지문 첫 줄 앞에는 페이지 채우기용 공백을 넣지 않는다. 마지막 쪽은 보통 문항 간격으로 마무리하고 나머지 공간을 그대로 둔다.

1. 한컴이 계산한 실제 문단·문항 높이와 첫 쪽/연속 쪽의 가용 높이를 측정한다. 원안지의 본문 하단은 용지 높이−아래 여백−꼬리말 여백=841.88−14.17−51.02=776.69pt이며, 이 환경의 실제 PDF에서는 약775.84pt이다. 바깥 테두리 하단 약788.5pt와 혼동하지 않는다. 쪽수를 먼저 고정하거나 모든 단을 같은 본문 높이로 가정하지 않는다.
2. 발문·보기/조건·선택지를 한 문항으로 유지하며 다음 문항을 앞쪽에 옮길 수 있는지 먼저 본다. 긴 지문은 문단/문장 경계에서 자연스럽게 이어 쓸 수 있다. 출처와 지문 끝, 공통 지시문과 첫 지문을 따로 고립시키지 않는다.
3. 본인 기출처럼 서술형을 관련 지문 근처에 배치하면 빈 공간을 줄일 수 있다. 선택형/서술형 각각의 번호와 참조 범위, 원본 후보 대응표를 갱신한다. 의미가 변하거나 답의 단서가 앞문항에서 노출되지 않는지 확인한다.
4. 짧은 선지는 실제 폭이 허용하면 가로/2열/3+2 배열로 정돈한다. 긴 선지까지 억지로 가로 배치하지 않는다. 선지 이어지는 줄은 원문자 뒤에 맞춘다.
5. **선택지①~⑤의 줄간격은160%, 선택지 사이 문단 위/아래 추가 간격은0**으로 둔다. 160%만 보고 정상이라고 판단하지 말고 문단 위/아래 간격과 빈 문단도 검사한다. 하단을 채우기 위해 선지 사이·보기/조건 내부 간격을 늘리지 않는다. 먼저 보기/조건 주변의 불필요한 추가 간격을 없애고, 문항/서술형 묶음을 재배치해 필요한 쪽수를 다시 계산한다. 그 뒤 문항 묶음 사이의 간격을 조절한다. 원안지 쪽수나 이전 샘플7쪽에 고정하지 않는다. 산문 `(가)~(나)` 사이의 불필요한 빈 줄을 만들거나 글자 크기·줄간격을 줄여 쪽수를 맞추지 않는다. 지문10pt·발문11pt는 유지한다.
6. 최종 쪽은 양쪽 단을 균형 있게 마무리하되 큰 배점표·그림·빈 상자를 지어내어 채우지 않는다. 일반 중간 쪽과 마지막 쪽의 공백은 구분한다.

## 검증

```bash
python scripts/check_school_form.py prepared.hwpx --pages N
python scripts/check_native_roundtrip.py --prepared prepared.hwpx --native final.hwpx --pdf final.pdf --reference-pdf original-hancom.pdf --expected-header exam-info.json --continuation-markers --strict-body-layout --passage-manifest sample-manifest.json
```

직접 편집한 승인 문구가 있으면 `--text-replacements replacements.json`에 정확한 이전/이후 문자열을 전달한다. 본문 변화를 자동으로 무시하는 옵션으로 쓰지 않는다.

검사기는 각 단의 마지막 본문 글자 또는 지문/보기/조건 테두리 바닥부터 사용 가능한 하단까지 측정한다. 이 사용자 프로필은 반드시 `--strict-body-layout --passage-manifest 작성명세.json`을 함께 사용한다. 이어짐 표시·외곽선·중앙선은 본문 점유량에 더하지 않는다. 원안지의 실제 본문 하단을 기준으로 비최종 단의 잔여 공백6mm 초과는 경고,10mm 초과는 실패로 본다. 오른쪽은 계속 표시 상단의 안전 간격도 반영한다. 이전 버전의 외곽선 기준20/40mm 검사는 기출의 배치 밀도를 보장하지 못하므로 이 사용자 시험의 완료 기준으로 쓰지 않는다. 이 수치는 기출 비교에 따른 검수 기준이며 원자료의 공식 규정이 아니다. 본문 마커 겹침, 마커 개수·홀짝·최종 생략, 누락/중복, 글꼴·크기·강조, 원본 틀/꼬리말/교표도 함께 검사한다. 모든 쪽을 직접 보아 간격의 자연스러움까지 확인해야 완료다.


2026-10-05 재검토: 이전 검증 샘플의 본문/조건 하단은734~745pt에 그쳤다. 본인 기출은750~776pt까지 사용한다. 단 끝의 큰 공백을 문항 사이로만 옮겨 숨기지 말고, 긴 지문은 필요한 경우 문장 경계에서 다음 단으로 이어 배치하고 글자·강조를 보존한다. 마지막 쪽도 적절한 문항 간격으로 균형 있게 정리하되 가짜 문항이나 빈 상자는 만들지 않는다. 사용자 재지적에 따라 선택지 추가 간격을 늘렸던1.6.1 방식은 폐기했다. `check_choice_spacing.py 결과.hwpx --manifest 작성명세.json`으로 선택지160%와 문단 간격0을 별도 검사한다.

## 2026-10-07 구분선 하단 기준

본문이 짧은 쪽을 포함하여 모든 쪽의 다단 세로선을 위 본문 하단 계산값까지 유지한다. 마지막 쪽의 넓은 본문 여백을 허용하는 규칙과 구분선의 끝높이는 별개다. 외곽선·꼬리말 위치를 바꾸지 않고, 다른 쪽의 짧은 선을 기준으로 복사하지 않는다. 자동 검사는 `check_exam_finish.py`로 쪽별 수행하고 실제 한글 출력도 확인한다.
