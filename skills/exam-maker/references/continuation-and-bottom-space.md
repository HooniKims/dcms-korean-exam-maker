# 이어짐 표시와 하단 배치

2026-10-05 사용자 지정: 본인 기출문제처럼 다음 쪽·다음 장 표시를 넣고 각 쪽 하단의 큰 공백을 없앤다. 원본 외곽선·꼬리말·교표의 위치를 바꾸지 않는다.

## 기출에서 직접 확인한 방식

`본인_출제모음/23-3-2-중간/2023-3-2-중간-국어-문제지(완성).hwp`의 한컴 PDF 1~4쪽은 홀수 `▶다음 쪽 계속`, 짝수 `▶다음 장 계속`, 마지막5쪽은 생략한다. 표시는 오른쪽 아래, 약10pt이다. `25-3-2-기말-국어-시험지(김형훈 추가 및 수정).hwp` 1~6쪽에서도 같은 홀짝 규칙을 `▶다음 쪽에 계속`/`▶다음 장에 계속`으로 쓰며 마지막7쪽에서 생략한다. 두 자료의 본문은 마지막 문항/조건을 하단 가까이 배치하고, 서술형을 관련 지문 주변에 넣거나 문항 간 간격을 조정한다. 짧은 선지는 가로 배치도 쓴다. 과거 검토용 정답 형광색과 일부 중복 마커는 새 시험에 복사하지 않는다.

## 적용할 규칙

- 이번 사용자 표현을 적용해 **홀수 쪽 `▶다음 쪽으로 계속`, 짝수 쪽 `▶다음 장으로 계속`**을 쓴다. 각 비최종 시험지 쪽에 정확히1개, 마지막에는0개다. 별도 답안지 유무를 시험지의 계속 표시에 섞지 않는다. 쪽수가 바뀌면 전부 재계산한다.
- 본문 프레임 안 우하단, 저작권·교표 위에10pt로 둔다. 본문/조건 상자와 겹치지 않도록 전용 하단 공간을 확보한다. 스페이스·탭·빈 문단을 반복해 바닥으로 밀지 않는다.
- 본문 앵커에 연결한 테두리 없는1셀 표처럼 한컴에서 안정적으로 유지되는 개체를 사용한다. 용지 기준 위치를 쓰고 꼬리말을 편집하지 않는다. 이 원안지 검증에서는 폭11000/높이2177 HWPUNIT, PAPER 기준 왼쪽43000/위77000, 내부 여백283, 오른쪽 정렬의1셀 표를 사용한다. 다른 양식에 수치를 무조건 적용하지 않는다. 저장 후 높이·위치·본문 겹침을 재검사한다.
- 실제 한컴2024 PDF 출력에서 사각형 글상자는 이후 페이지의 숫자 출력 정밀도를 낮춰 기존 꼬리말 글자를 약0.3mm 이동시켰다. 모양만 비슷하다고 합격시키거나 비교 허용치를 늘리지 말고, 테두리 없는 표 등으로 바꾸어 재출력한다.

## 하단 공백 줄이기

**2026-10-07 최신 사용자 지시가 과거의 마지막 쪽 예외·간격 상한보다 우선한다.** 이 사용자의 시험지는 마지막 쪽을 포함해 모든 쪽의 양쪽 단을 하단 가까이 채운다. 이미 확정된 문항·정답·번호를 유지하고, 남는 공간은 문항 묶음 사이의 문단 앞 간격으로 분배한다. 과거의 “마지막 쪽은 큰 여백을 허용”, “8/18pt까지만 늘림”을 이 사용자에게 다시 적용하지 않는다. 다른 사용자의 문서에는 별도 요청 없이 이 규칙을 강제하지 않는다.

1. 한글이 저장한 실제 줄 좌표·표 높이로 각 단의 마지막 본문 위치와 잔여 높이를 측정한다. 본문 하단은 용지 높이−아래 여백−꼬리말 여백이며, 외곽선·저작권·교표의 위치를 옮겨 하단을 채우지 않는다. 오른쪽 단은 계속 표시 위의 안전 간격을 남긴다.
2. 먼저 짧은 지문 시작 조각을 해결한다. 안내문과 지문 몇 줄만 인쇄된 뒤 다음 쪽으로 넘어가면 안내문부터 다음 쪽으로 함께 옮긴다. 기본 검사 기준은 시작 쪽에 본문5줄 미만만 남고 지문이 다음 쪽으로 이어지는 경우이며,5줄 이상이어도 전체 지문에서 지나치게 작은 조각이면 시각 검토로 이동한다. 원래 완결된 짧은 지문은 오류가 아니다. 같은 쪽의 좌→우 단 이어짐과 다음 쪽 넘김을 구별한다. 긴 지문 전체를 무조건 분할 불가로 만들어 넘침을 유발하지 않는다.
3. 페이지 시작 문단을 바꿀 때 그 문단에 붙은 상단 정보표·계속 표시·중앙선 개체도 새 첫 문단으로 옮긴다. 실제 쪽수와 No.:n/N을 대조한다. 자연 넘김 직후 불필요한 강제 단 나눔을 남기지 않는다.
4. 배치가 정해지면 각 단의 잔여 높이를 해당 단의 문항/지문 묶음 경계에 고르게 나눈다. 첫 문단의 위 여백을 늘려 상단을 비우지 않는다. 문단 앞 간격 전용 스타일을 복제해 사용하며 공백 문자·빈 문단 반복으로 밀어내지 않는다. 단을 가로질러 이어지는 지문은 간격 변화가 다음 단의 줄 수에 미치는 영향까지 다시 계산한다.
5. **선택지①~⑤는160%, 선택지 사이 문단 앞뒤0**을 유지한다. 보기·조건·지문 내부의 간격, 글자 크기, 발문과 선택지의 결합을 훼손하지 않는다. 문항 간격을 늘리는 사용자 지시를 선택지 간격 확대와 혼동하지 않는다. 지문10pt·발문11pt, 정답 형광펜, 출처·좌우 테두리 대칭을 보존한다.
6. 마지막 쪽에 서술형 한 문항만 있어 나눌 문항 경계가 부족하면 실제 답안 작성 공간을 넓혀 하단까지 사용한다. 필요한 쓰기 줄을 더하고 간격을 고르게 맞추되 답안선의 좌우 대칭과 부분점수 조건을 유지한다. 점수 집계는 답안 공간 뒤의 하단에 배치한다. 가짜 문항·장식용 상자·빈 표로 채우지 않는다. 답안 줄 수 변경은 검수 기록에 남긴다.
7. 간격 조정 뒤 반드시 다시 저장·PDF 출력한다. 페이지가 추가되거나 문항이 통째로 밀렸다면 해당 단의 간격을 재계산한다. 모든 쪽의 하단 잔여 공간, 지문 첫머리, 문항-선지 결합과 계속 표시 간섭을 확인한다. 첫 계산값이나 예정 쪽수만으로 완료를 선언하지 않는다.

## 검증

```bash
python scripts/check_school_form.py prepared.hwpx --pages N
python scripts/check_native_roundtrip.py --prepared prepared.hwpx --native final.hwpx --pdf final.pdf --reference-pdf original-hancom.pdf --expected-header exam-info.json --continuation-markers --strict-body-layout --fill-final-page --passage-manifest sample-manifest.json
```

직접 편집한 승인 문구가 있으면 `--text-replacements replacements.json`에 정확한 이전/이후 문자열을 전달한다. 본문 변화를 자동으로 무시하는 옵션으로 쓰지 않는다.

검사기는 각 단의 마지막 본문 글자 또는 지문/보기/조건 테두리 바닥부터 사용 가능한 하단까지 측정한다. 이 사용자 프로필은 반드시 `--strict-body-layout --fill-final-page --passage-manifest 작성명세.json`을 함께 사용한다. 이어짐 표시·외곽선·중앙선은 본문 점유량에 더하지 않는다. 원안지의 실제 본문 하단을 기준으로 마지막 쪽을 포함한 모든 단의 잔여 공백6mm 초과는 경고,10mm 초과는 실패로 본다. 현재 사용자 최종 검수에는 `--fill-final-page`가 필수다. 오른쪽은 계속 표시 상단의 안전 간격도 반영한다. 이전 버전의 외곽선 기준20/40mm 검사는 기출의 배치 밀도를 보장하지 못하므로 이 사용자 시험의 완료 기준으로 쓰지 않는다. 이 수치는 기출 비교에 따른 검수 기준이며 원자료의 공식 규정이 아니다. 본문 마커 겹침, 마커 개수·홀짝·최종 생략, 누락/중복, 글꼴·크기·강조, 원본 틀/꼬리말/교표도 함께 검사한다. 모든 쪽을 직접 보아 간격의 자연스러움까지 확인해야 완료다.


과거 선택지 간격을 늘린1.6.1 방식은 계속 폐기한다. 최신 지시는 문항 묶음 사이와 실제 서술형 작성 공간에만 적용한다. `check_choice_spacing.py 결과.hwpx --manifest 작성명세.json`으로 선택지160%와 앞뒤0을 검사한다.

## 2026-10-07 구분선 하단 기준

본문이 짧은 쪽을 포함하여 모든 쪽의 다단 세로선을 위 본문 하단 계산값까지 유지한다. 마지막 쪽도 하단을 채우며 구분선은 본문 길이와 관계없이 같은 끝높이를 유지한다. 외곽선·꼬리말 위치를 바꾸지 않고, 다른 쪽의 짧은 선을 기준으로 복사하지 않는다. 자동 검사는 `check_exam_finish.py`로 쪽별 수행하고 실제 한글 출력도 확인한다.

## 2026-10-07 자연 넘김 직후 강제 나눔 회귀

실제 시험지에서 예정 7쪽이 한글 조판 후 8쪽이 되었다. 6쪽의 긴 지문 마지막 줄이 오른쪽 단으로 자연 이동했는데, 다음 지문 문단에 남아 있던 `columnBreak=1`이 다시 이동시켜 거의 빈 단과 상단 정보 없는 쪽을 만들었다. 저장된 직계 본문 문단의 `linesegarray/lineseg@vertpos`가 문단 안에서 큰 값에서 작은 값으로 되돌아간 뒤 다음 문단에 강제 단 나눔이 있으면 우선 의심한다. 표 셀 내부 줄 좌표는 이 판단에 섞지 않는다.

`check_exam_flow.py`는 이 조합을 검수 오류로 보고한다. 의도된 나눔일 수도 있으므로 검사기가 자동 삭제하지 않는다. 실제 쪽을 본 뒤 불필요한 나눔을 제거하거나, 넘김 전 문장 경계로 옮기고 문항 간격을 다시 측정한다. 문항·정답·배점을 바꾸어 이 오류를 숨기지 않는다. 수정 후 저장·재열기·PDF 출력 쪽수와 정보표 수를 다시 맞추고, 원고 및 manifest의 캐시도 갱신한다.
